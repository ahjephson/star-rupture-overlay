# Recipe tracker

Status: version 0.2.6 development candidate. Manual testing confirmed the counter appearance and fast outside-station clearing on 2026-10-27. The running candidate was switched separately; full release checks remain as listed below.

## Operation

Open Settings and use the Recipe tracker section to enable the panel, change its shortcut, select an upper/middle/lower right position or choose 75–150% scale. The default shortcut is Alt+X. Hover over a recipe row in the station and press the shortcut once to pin it. Hover over another unfinished recipe and press it to switch. Use the shortcut on the same unfinished recipe to clear. Outside the station it clears a pinned recipe even while the mouse moves or recenters, and otherwise does nothing. In the station, no hovered row or a completed recipe leaves the selection unchanged. The tracker prepares when it connects to the game. Reopening the station uses its current menu references. Holding the keys does not repeat the action. Shortcuts register while the game has focus and are released when focus leaves it or the app closes. Conflicts appear in Settings.

The upright title icon uses the native half-opacity grey frame, rotated to point downward beyond the square. The title and icon identify the pinned research recipe. Vertical tiles show its research materials, submitted/required amounts and completed requirements. Those counts are research payments, not inventory or manufacturing inputs. A new panel appears only after a successful read; the previous panel remains visible while switching. The narrow panel keeps tracking after the station closes. Any positive bag quantity makes the fraction white and adds an orange count inside the tile; zero bag quantity makes it red. Counters align to the left inside each tile. Partial submitted amounts use two lines with the game's spacing, black outline and drop shadow. Invalid, changing, missing or stale evidence displays unavailable counts. A recipe disappearing from the live research list does not by itself establish completion.

## Prepare local assets

Use read-only exports from the supported game build. `scripts/Import-RecipeAssets.ps1` accepts a normalized native `catalogue.json`, an exported texture directory, the native Nippo-Regular `.ufont` file and a new output directory. It follows the catalogue's exact icon references, validates the font envelope, converts images to premultiplied BGRA and writes a build-bound recipe reference and provenance manifest. The caller provides the exports; the script does not download or modify the game.

Place the output in `recipe-assets/` beside the candidate executable. Keep this pack local and outside Git or standard release archives. Standard packaging and deployment checks continue to cover the application without game assets; a local tracker candidate includes its separately imported pack. Preserve both folders when preparing a manual test. Native fonts are registered only in the overlay process.

## Implementation

Broad object discovery is confined to connection setup and at most two bounded setup-recovery attempts. Normal capture, clearing and menu reopening do not enumerate the object registry. They follow the current local player's viewport/game-instance ownership, the UI manager's policy and matching attached layout, then the menu stack's displayed inventory screen. The visible recipe table is resolved through that screen's owned widget references. Recipe rows come from the table's crafter and recipe panels. Missing, ambiguous or unattached player layouts are unavailable, never treated as a closed station. The menu stack's validated empty displayed-widget reference establishes closure.

All links, local-player ownership, object classes/serials, visibility and collection headers/contents are reread before an observation is accepted. Opening/closing a menu replaces its references naturally; no per-opening global warmup or negative registry scan is needed. The recipe reader diagnostic asserts zero global scans across its context/capture/sample checks.

The existing worker retains exclusive ownership of the process handle and performs all game reads. Build-pinned reflected layouts establish the recipe owner, requirements arrays and recipe-row references. Native widget code establishes cached Slate hover and owning-player context bindings; Capture checks the recipe table's native activation flag, owning player, visible widget ancestry and active inventory-screen root, with allocation and pointer rereads. A validated outside-station request clears the current pin while the game retains focus; it does not require a cursor position. Station-row capture still requires the cursor to remain over the requested target. Read failures preserve the pin. In the station, capture validates row class, player weak reference, widget allocation, visible station ancestry, native hover flag and recipe identity before retaining a native recipe asset ID. It does not invoke widget functions or debug unlock handlers. Persistent tracking reads the recipe owner's counters with allocation/header/content and world/owner rereads. The pinned recipe-record location is a hint revalidated on reuse. Bag quantities join current-character owned handles to the matching item store, with allocation, handle, count and array rereads. Bag reads do not include depot stock. Missing bag evidence remains unknown. Required amounts come from the matching native reference pack; ingredient mismatches and duplicate or invalid counts stay unavailable.

Pin and clear requests carry a generation. A cleared or replaced request rejects delayed worker results. Process/world reacquisition clears the pin. Failed shortcut reads leave a diagnostic message in the local app log. Recipe sampling is bounded and shares the existing worker, cancellation and process guards; it does not add a watcher, second resident reader or MCP dependency. The recipe panel has its own click-through window and rendering resources and follows the existing game window ordering rules. Wave observation contracts and timing calculations remain unchanged.
